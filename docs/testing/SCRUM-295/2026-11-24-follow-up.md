## Confirmed metrics defect and proposed fix (NOT applied)

The original failing snapshot was PR #187 at `e8bca50722324279df6be686843949b06a212500`. That PR has since merged at owner head `e4e480ab3b96fb6eec5ec0085ef9bdb87252522e`, advancing develop to `e9de4167a5d669289461b5054b5f0a28f8238358`. The owner update did **not** change the prefix exclusion; a follow-up fix is still needed.
`RequestMetricsFilter.shouldNotFilter()` currently checks `path.startsWith("/actuator")`.
The contract excludes actual `/actuator/*` endpoints. The unrelated ordinary
`/actuator-not-an-endpoint` is therefore wrongly excluded: a 404 produces total
request delta **0**, whereas it must produce **1**.

Proposed change for Moustafa, retaining the existing normalized `pathOf(request)`:

```diff
- return path.startsWith("/actuator") || METRICS_PATH.equals(path);
+ return "/actuator".equals(path)
+         || path.startsWith("/actuator/")
+         || METRICS_PATH.equals(path);
```

This preserves exclusion of `/actuator`, `/actuator/health`, other genuine actuator
paths and `/api/admin/metrics`; ordinary `/actuator-not-an-endpoint` and similar
prefix lookalikes are counted. The existing failing regression remains unchanged.
Only the owner should apply a follow-up production fix on develop and rerun his tests plus our 17 criteria. This proposal has not been applied to production code or submitted to a teammate PR.
